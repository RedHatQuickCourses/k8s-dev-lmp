#  API-centric declarative configuration management

= API-Centric Declarative Configuration Management

Kubernetes is fundamentally an API-centric system. Unlike traditional infrastructure management where you might run a sequence of imperative commands (e.g., "start container X," "open port Y"), Kubernetes operates by observing the **desired state** provided by the user and reconciling it against the **actual state** of the cluster.

== The Declarative Paradigm

In a declarative system, you describe the *what*, not the *how*. You submit a manifest—usually in YAML or JSON—to the Kubernetes API server, stating exactly what your application should look like.

*   **Imperative:** "Run this container, then scale it to three replicas, then attach a storage volume."
*   **Declarative:** "I want a `Deployment` object with three replicas, using image `nginx:latest`, and a `PersistentVolumeClaim` attached."

The Kubernetes control plane treats this manifest as the "source of truth." Once submitted, the system continuously works to ensure that the cluster's current state matches your declared intent. If a container crashes, the controller notices the discrepancy between the desired state (3 replicas) and the actual state (2 replicas) and automatically spins up a new instance.

== The Heart of the System: The API Server

The `kube-apiserver` acts as the central gateway for all interactions. It provides a RESTful interface that allows components to communicate, store, and retrieve state.

[NOTE]
====
The API server is the only component that communicates directly with `etcd`, the persistent key-value store. By acting as the sole interface for state changes, the API server ensures that all cluster operations go through validation, authentication, and authorization before being persisted.
====

### The Request Lifecycle
When you send a configuration to the cluster (e.g., via `kubectl apply`), the following high-level process occurs:

1.  **Authentication/Authorization:** The `kube-apiserver` verifies who you are and if you have permissions to perform the action.
2.  **Admission Control:** Webhooks may inspect, reject, or modify the request (more on this in Week 3.1).
3.  **Persistence:** Upon successful validation, the object is stored in `etcd`.
4.  **Reconciliation:** Controllers (watching the API server) observe the new state and perform the necessary work (like scheduling pods or mounting volumes) to bring the cluster to that desired state.

== Hands-On Activity: Observing Declarative State

In this exercise, you will observe how the API server manages declarative intent.

### Prerequisites
*   A running Kubernetes cluster (e.g., Minikube, Kind, or OpenShift).
*   `kubectl` installed and configured.

### Step 1: Create a Declarative Manifest
Create a file named `nginx-deployment.yaml`:

[source,yaml]
----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
----

### Step 2: Apply the Intent
Apply the configuration to your cluster:

[source,bash]
----
kubectl apply -f nginx-deployment.yaml
----

### Step 3: Observe the Reconciliation
After applying, verify that the system is acting on your behalf:

[source,bash]
----
kubectl get deployments
kubectl get pods
----

### Step 4: Simulate a Failure
Manually delete one of the pods managed by your deployment:

[source,bash]
----
# Replace <pod-name> with the actual name of one of your nginx pods
kubectl delete pod <pod-name>
----

Observe the system behavior immediately after:

[source,bash]
----
kubectl get pods
----

**Expected Result:** You will see that Kubernetes has already initiated a new pod to replace the one you deleted. This confirms the **declarative** nature of the system: the `kube-apiserver` and its controllers are constantly maintaining the state you declared in your YAML file, regardless of external disruptions.
