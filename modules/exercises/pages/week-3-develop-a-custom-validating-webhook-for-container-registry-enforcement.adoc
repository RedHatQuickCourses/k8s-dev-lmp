#  Week 3: Develop a custom Validating Webhook for container registry enforcement

= Week 3: Develop a Custom Validating Webhook for Container Registry Enforcement

In this exercise, you will extend your Kubernetes expertise by intercepting API requests to enforce governance. Specifically, you will build a **Validating Admission Webhook** that acts as a gatekeeper, preventing the creation or update of resources that reference unauthorized container registries.

== Prerequisites
* A running Kubernetes cluster (e.g., `kind` or `minikube`).
* `cert-manager` installed in your cluster (for managing webhook TLS certificates).
* Go 1.20+ installed.

== Understanding Admission Webhooks
Kubernetes Admission Controllers are plugins that govern and enforce policies on objects during create, update, or delete operations. 
* **Validating Webhooks:** Allow you to reject requests that do not meet your criteria.
* **Mutating Webhooks:** Allow you to modify objects (e.g., adding default sidecars) before they are persisted to `etcd`.

== Hands-on Lab: Registry Enforcement Webhook

### Step 1: Define the Webhook Logic
Create a Go HTTP server that implements the `admission.k8s.io/v1` `AdmissionReview` interface. Your logic needs to inspect the `AdmissionRequest` object.

[source,go]
----
func handleRegistryValidation(w http.ResponseWriter, r *http.Request) {
    // 1. Decode AdmissionReview from r.Body
    // 2. Check if object contains image field
    // 3. Compare image prefix against allowed registries
    // 4. If invalid, set response.Allowed = false and provide a message
    // 5. Encode AdmissionReview and write to w
}
----

### Step 2: Implement Registry Enforcement
The binary must accept a list of approved registries via command-line flags. Use the `flag` package to capture these inputs during startup.

[source,go]
----
var allowedRegistries []string

func init() {
    flag.Func("allowed-registries", "Comma-separated list of approved registries", func(s string) error {
        allowedRegistries = strings.Split(s, ",")
        return nil
    })
}

func isImageAllowed(image string) bool {
    for _, reg := range allowedRegistries {
        if strings.HasPrefix(image, reg) {
            return true
        }
    }
    return false
}
----

### Step 3: Configure the ValidatingWebhookConfiguration
You must register your webhook with the `kube-apiserver` by creating a `ValidatingWebhookConfiguration` object. This tells Kubernetes where to send the `AdmissionReview` requests.

[source,yaml]
----
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: registry-validator
webhooks:
  - name: validate.registry.example.com
    rules:
      - operations: ["CREATE", "UPDATE"]
        apiGroups: [""]
        apiVersions: ["v1"]
        resources: ["pods"]
    clientConfig:
      service:
        name: webhook-service
        namespace: default
        path: "/validate"
    admissionReviewVersions: ["v1"]
    sideEffects: None
----

### Step 4: Deploy and Verify
1. **Build and Containerize:** Create a Dockerfile for your webhook binary and push it to a registry.
2. **Deploy:** Apply your `Deployment` and `Service` to the cluster.
3. **Test:** Attempt to create a Pod using an unauthorized image:

[source,bash]
----
kubectl run unauthorized --image=docker.io/library/nginx:latest
# Expected Result: Error from server: admission webhook "validate.registry.example.com" denied the request
----

== Key Considerations
* **Fail Policy:** In production, set `failurePolicy: Fail` (to block if the webhook is down) or `failurePolicy: Ignore` (to allow requests if the webhook is unreachable).
* **TLS Requirements:** The `kube-apiserver` requires HTTPS to communicate with your webhook. Ensure your `ValidatingWebhookConfiguration` includes the `caBundle` generated by `cert-manager`.
* **Testing:** Always use `dry-run` during development to verify your webhook behavior without accidentally locking yourself out of the cluster.
