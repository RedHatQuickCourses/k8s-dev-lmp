Welcome to this course on Kubernetes architecture and its powerful extensibility mechanisms. Throughout this training, we will provide a comprehensive overview of how the Kubernetes API functions behind the scenes, specifically exploring how the control plane handles authentication, authorization, and validation for cluster requests. The primary focus of this course is platform automation; you will learn how to extend Kubernetes by defining custom resources and developing custom controllers or operators to manage your workloads automatically.

Let’s take a look at the learning roadmap.

To begin, we will orient you with the fundamentals of Kubernetes. As an API-centric, declarative system, it is vital to understand how the API server, etcd, and various controllers work in harmony.

In our first module, we explore the Kubernetes resource model. We will walk through the essentials of the kube-apiserver, covering the declarative intent of resources and the various plugin layers, including authentication, audit, impersonation, priority and fairness, authorization, admission, and storage.

Next, we move to the building blocks behind operators, specifically focusing on controllers, informers, and the client-go library. You will learn about the architecture of client-go, as well as the use of informers, listers, workqueues, caches, and essential error-handling patterns.

Following that, we will dive into building controllers using controller-runtime. This session covers the reconcile loop, how to use kubebuilder, managing spec versus status, handling conditions, API validation, and performing CRUD operations, including the differences between apply, patch, and update.

In the fourth module, we address the challenges of distributed systems. We will examine topics like idempotency, locks, leases, leader election, and controller sharding, using the OpenShift Ingress Controller as a real-world case study.

As we progress, we will take more control by exploring admission control webhooks and even how to write your own API server. This includes validating and mutating webhooks, policy engines, API discovery, aggregated APIs, and custom API servers. 

We will then cover essential supporting topics, including networking with Ingress and the Gateway API, Service Mesh, authentication and authorization in OpenShift, and cluster security hardening.

Finally, we will conclude with a deep dive into the kube-scheduler, including scheduling and de-scheduling, resource requests and limits, and dynamic resource allocation. We will finish the course by looking at the broader operator landscape and alternative control plane architectures, such as HyperShift, kcp, MicroShift, and k3s.

Please proceed to the first module when you are ready to begin.
