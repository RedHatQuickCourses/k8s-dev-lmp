Welcome to module 1.2, covering Controllers, Informers, and the client-go library.

In this module, we will examine the fundamental building blocks that power every Kubernetes operator and controller. We begin by looking at the architecture of client-go, which is the official Go client library. Specifically, we will break down its core components: the Reflector, the DeltaFIFO queue, the Indexer, and the SharedInformerFactory. You will see how these pieces form a complete pipeline, moving data from the Kubernetes API server all the way to your controller logic.

From there, we will explore the Informer, Lister, and Workqueue pattern. This pattern is critical because it decouples event delivery from the reconciliation process. We will walk through the official sample-controller code, line by line, and discuss common production pitfalls that typically only surface when running at scale.

It is important to note that these components form the foundational layer that controller-runtime abstracts over. A solid understanding of this layer is essential; it will help you debug operator issues effectively and allow you to recognize when those higher-level abstractions are helping you, and when they might be hiding underlying problems.
