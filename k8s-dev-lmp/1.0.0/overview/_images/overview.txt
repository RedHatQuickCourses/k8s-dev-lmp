Welcome to this course, which provides a comprehensive overview of Kubernetes architecture and its powerful extensibility mechanisms. We will begin by exploring how the Kubernetes API functions behind the scenes, specifically looking at how cluster requests are authenticated, authorized, and validated by the control plane. The core of this course focuses on platform automation, teaching you how to extend Kubernetes by defining custom resources and writing custom controllers or operators to automatically manage your workloads.

Let’s take a look at our course roadmap.

We start with an orientation on how the API server, etcd, and controllers work together, as Kubernetes is, at its core, an API-centric, declarative configuration management and container orchestration system.

In module 1.1, we cover the Kubernetes Resource Model. This is a walkthrough of the essentials of the kube-apiserver, focusing on the declarative intent of Kubernetes resources and the various plugin layers, including authentication, audit, impersonation, priority and fairness, authorization, admission, and storage.

Next, in module 1.2, we discuss Controllers, Informers, and client-go. Here, we examine the basic building blocks of operators, including client-go architecture, Informers, listers, workqueues, caches, and error handling.

Module 2.1 moves into writing concrete Kubernetes APIs using controller-runtime. We will cover the reconcile loop, kubebuilder, the differences between specifications and status, conditions, API validation, and various CRUD operations including apply, patch, and update.

In module 2.2, we tackle the challenges of distributed systems. We’ll cover topics such as idempotency, locks, leases, leader election, and controller sharding, featuring a case study on the OpenShift Ingress Controller.

Moving into module 3.1, we take more control by looking at admission control and writing your own API server. This includes working with validating and mutating webhooks, policy engines, API discovery, aggregated APIs, and custom API servers.

In module 3.2, we cover additional essential topics, including networking with the Ingress and Gateway APIs, service meshes, authentication and authorization in OpenShift, security, and cluster hardening.

Module 4.1 is a deep dive into the kube-scheduler. We will explore scheduling, de-scheduling, resource requests and limits, and dynamic resource allocation.

Finally, in module 4.2, we cover the broader landscape of operators and alternative control plane architectures, including HyperShift, kcp, MicroShift, and k3s.

Please proceed through these modules in order to build your foundational knowledge and skills in Kubernetes extensibility.
